1. 每次先核对当前时间、计划状态、Git 分支、远程地址和工作区。若远程或分支改变、目标文件有无法安全合并的用户修改、暂存区存在无关内容，停止并通知用户。不要丢弃、改写或提交别人的改动。
2. 从指定 Git 快照提取文件，不使用源项目工作区中未提交的改动。不要复制 `.git`、`node_modules`、私有开发者配置、凭证或临时文件；不要把 `联网版本/` 作为嵌套仓库加入目标仓库。
3. 自动运行仅处理最早到期且未完成的一批，不在一次自动运行里补齐所有批次。2026-10-10 用户重新授权的人工续做可按顺序完成剩余第 5、6 批，仍须各批独立验证和提交。没有实际变更时不创建空提交；根据内容与历史判断是否已完成，并如实说明。
4. 每批至少运行根目录 `npm test`、`npm run check`，保证本地版未受影响。检查新迁移的 JS 语法及 JSON 格式；第 2–3 批运行已存在的后端/数据层测试，第 4–6 批执行 `cloud-version/` 的 `npm test`、`npm run check`。第 6 批核对所有页面、组件和引用路径。
5. 更新下方执行记录，写清实际时间、测试结果和待确认事项。只暂存本批明确路径和计划文档，先审查暂存差异，再用计划中的提交说明提交。提交使用 Git 当前真实时间。
6. 推送前核对远端 `main`；只允许正常快进推送。遇到远端新增提交或冲突，先停止并说明，不强推、不重置、不自动改写历史。
7. GitHub 使用既有凭证；目标账号为 `boluoyellow`。可按本机已验证方式使用 OpenSSL 后端与 HTTP/1.1，禁止关闭证书验证或输出凭证。需要登录或额外权限时通知用户，不修改安全设置以绕过限制。
8. 提交已生成但推送失败时，下一次只重试该提交的推送；不要重复迁移或制造第二个相同提交。以远端包含提交为完成依据，并在下一批提交中补记其哈希。
9. 无到期工作时保持安静。只在实际完成一批、完成全部、发生失败或需要用户处理时通知。全部成功或到达截止时间后结束此迁移任务；后续唤醒不得继续改动或推送。
